# 产品范围：用户确认的 Ignition 工程工作台

记录日期：2026-11-17，依据本次语音澄清。此文件记录需求，不表示用户已批准具体技术实现。

## 要做的产品

类似 DeepSeek Harness 的桌面工程壳子，集中完成原来分散在 Ignition Designer、Gateway Web 管理页面与 Perspective 浏览器中的工作。不能把产品缩减为一个 MCP 聊天客户端，也不能把 Gateway 配置、Tag 和数据库浏览排除在最终范围外。

| 编号 | 用户要求 | 完成时用户能看到的结果 |
|---|---|---|
| REQ-01 | 左侧 Project 栏管理不同项目 | 多个 Gateway 的项目可添加、切换；明确显示当前操作目标 |
| REQ-02 | 添加 Project 时类似 Designer 登录，保存登录状态 | 用户完成交互登录；重开工作台可恢复；失效时有明确状态 |
| REQ-03 | Session 长期连接 | 工作台切换面板不中断连接；断网、Gateway 重启后恢复；服从服务器有效期 |
| REQ-04 | 直接操作 Gateway，新增及修改点位 | 区分 Tag 配置编辑与实时值写入；看到逐项结果和最新树结构 |
| REQ-05 | 新增及修改画面 | 直接更新 Gateway 项目资源，无须人工回 Designer 保存 |
| REQ-06 | 新增及修改脚本 | 覆盖项目库、Gateway 事件、画面/组件脚本等不同宿主 |
| REQ-07 | Gateway Web 配置也在工作台内操作 | 支持相应配置编辑和状态反馈；未覆盖页面可在内置浏览器打开 |
| REQ-08 | 内置浏览器实时预览 Perspective 变化 | 预览真实运行会话，显示实际生效版本和连接状态 |
| REQ-09 | Tag 树、点位值和数据库预览 | 按需浏览、订阅/刷新及分页，操作后同步更新 |
| REQ-10 | 先研究清楚 Ignition 和版本，再进入开发 | 有接口证据和明确连接路线，不用假设的 API 直接搭产品 |

## 版本基线

- 产品目标保留原始要求：Ignition **8.3.9 及后续 8.3.x**。Artek-MCP 供应商给出的最低版本是 **8.3.4**，这是模块门槛，不是把产品最低版本改为 8.3.4；语音中的版本转写不作为另一条 8.4.x 基线。
- Catalyst 必须研究具体 **2027.2.0-beta1** 制品，不能仅用滚动更新的 `/docs/2027/` 页面替代版本证据。
- 用户强调该 Beta 是此次 Catalyst 研究对象。本项目不据此声称已证明 Catalyst 在所有其他发行版本的存在或缺失。

## 需要保持的领域区分

Project 是项目资源边界；Tag Provider、数据库连接和大量 Gateway 配置属于 Gateway 范围。Project 栏可以承载它们的入口，但修改共享资源时必须显示 Gateway、Provider/连接名与受影响范围。项目里的默认 Tag Provider/数据库只是默认引用，不表示资源归该项目独占。

用户希望体验统一；服务端的工程身份、MCP/API 授权、Gateway Web 会话和 Perspective 运行身份仍需要正确对应，不能用一个管理员 API key 冒充用户完成了 Designer 身份登录。

本轮继续完成研究、接口证据和建议路线，直接推送远端。尚未授权某个最终技术设计，不提前交付一个仅有 UI 或 mock 的“完成版”。研究建议见 [深入技术调查](technical-investigation.md)。
