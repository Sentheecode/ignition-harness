## 0. 边界和隔离检查

全部勾选后才能进行真实环境操作；不满足就记录阻塞，不通过放宽权限、替换生产地址或开发 UI 绕过去。

- [ ] 新建专用测试实例；不复用任何生产或生产性质 Gateway、生产备份、卷、账号或网络。
- [ ] 路径 A 为 **8.3.9 + 固定版本 Artek-MCP**；路径 B 为 **2027.2.0-beta1 + Catalyst Core/Agent**。模块门槛与产品版本基线分别记录。
- [ ] 镜像来自官方来源，记录标签、解析得到的 digest、CPU 架构和实际运行 build；不能只凭 Docker Hub 标签判断已启动成功。官方标签出处见 PR #1 的 Docker 元数据，实际 digest 仍由该次创建环境核验。
- [ ] 两实例使用独立新卷、端口、凭据和浏览器 profile。不要复制旧生产配置、shared volume、session 或 token；端口按空闲情况选择并记录，不能假定历史端口仍空闲。
- [ ] 仅向本机暴露测试端口，限制网络；无 PLC、OPC 设备、生产数据库、Gateway Network/EAM/冗余连接或其他可触达生产的出站集成。
- [ ] 只有合成 Memory Tag、测试项目与独立测试数据库；Web 预览不登录真实生产项目。
- [ ] 用户/操作者按官方条款完成安装与 EULA；记录 edition、模块状态、license/trial、模型提供者配置情况。不自动同意条款、提交供应商个人资料或改变许可状态。
- [ ] Artek 安装包由授权渠道提供，记录版本、来源、SHA-256；仓库不添加 `.modl` 或其他第三方模块二进制。尚未取得模块时 A 路径保持 blocked，不能用原生 API 测试冒充该组合通过。
- [ ] 在仓库外准备 700 私有目录、600 的凭据文件与脱敏字面量清单。明确 endpoint 属于新建测试实例。

采集脚本要求 `--isolated-test-gateway` 和 metadata 中两项 true。这是人为防误用检查，不是自动识别生产系统的保证。

## 2. View 单次写入—真实预览—恢复（两版本各一次）

每条路径只对新建的自有测试项目操作。此处描述步骤，不预填任何工具名、资源路径或认证头。所用合同必须来自该实例工具 schema、已核验文档或目标 OpenAPI。

### 2.1 先证明可恢复

- [ ] 新建/选定仅属于本实验的项目和简单 View；只用合成数据。设定唯一、无副作用的可见文本变更，例如从 `Lab baseline` 改为 `Lab changed`。
- [ ] 从该目标读取原始资源及所有文件/元数据；私有保存备份与 View 内容 SHA-256。若使用项目 ZIP，保留全部未知资源与 metadata，不重建或分发供应商二进制。
- [ ] 记录读取/写入合同的来源、实际工具/方法名、参数、资源归属、权限；**若没有可验证写入合同则停止**，不能猜 URL 或追加万能脚本执行桥。
- [ ] 明确恢复操作和读回校验方式。原地修改现有测试 View，并保留原始内容，可避免把删除项目当作“恢复”。
- [ ] 浏览器打开目标的真实 Perspective 测试会话，记原始可见文本、时间、连接状态和页面导航计数；浏览器地址来自该实例，不套用历史模板。
- [ ] 确认没有并行编辑者；读取当前 signature/内容确认仍与备份一致。普通 read/hash/write 不是原子并发控制，需如实标记。

### 2.2 只做一次受控变更

- [ ] 使用已证实合同提交**一次** View 文本修改。记录响应成功字段、逐项失败和新 signature（如有），不只看 HTTP 200。
- [ ] 不改 Tag、脚本、数据库连接、模块、权限、Gateway 其他配置；不通过重启 Gateway 掩盖热更新失败。
- [ ] 从 Gateway 再读资源，确认实际保存了目标文本；仅有本地文件改变不算写入通过。
- [ ] 当前真实 Perspective 会话显示变更；记录等待耗时、内容、连接状态、是否自动重载及主页面导航次数。截图来自真实 runtime，不是重绘 UI。
- [ ] 超时或断线分别记失败/未知；没有可观察的运行结果不能用“提交已接受”代替“预览通过”。

### 2.3 无论成功与否都恢复

- [ ] 一旦可能已发出修改请求，即进入恢复检查；超时不能当作未写入，也不自动重试同一修改。
- [ ] 先读回判断实际状态；如存在意外并发变化，停止覆盖并保留 blocked/人工恢复记录。只恢复本实验的自有资源。
- [ ] 用已验证合同恢复原始 View 内容及需要保留的 metadata，不删除其他资源；记录恢复响应。
- [ ] 从 Gateway 读回并比较原始 View 内容摘要；ZIP 容器时间戳或服务器重写的 signature 单独解释，不与内容恢复混为一谈。
- [ ] 原 Perspective 页面重新显示 `Lab baseline`，记录恢复后预览、连接状态和导航数。
- [ ] 发布“原始 → 修改 → 恢复”三状态的脱敏证据。恢复失败是整个闭环失败，**不能宣称单次 View 闭环通过**。

## 3. 刷新与冲突单独验收

- [ ] 写入后资源读回与浏览器预览分别记录；用户手动刷新、页面自动 reload、现有会话热更新分别分类，不混称无刷新。
- [ ] 对实际发现且支持 expected signature/version 的同一资源合同，保留旧版本，在专用测试资源上提交一次过期前提；应拒绝覆盖，再读确认新版本未被旧内容替换。
- [ ] 没有公开条件写入合同：记录“未发现/未验证原子冲突”，不能通过两次普通 GET 或客户端 hash 宣称解决并发。
- [ ] 不预设冲突必为 409；记录实际状态与去敏后的机器可判定错误，再确认内容。HTTP 200 内失败也算失败。
- [ ] Gateway **配置资源**的冲突测试若另行安排，使用独立、可恢复资源并独立记录；其结果不能外推为 View/项目导入的冲突保障。
- [ ] 只测试合成 Memory Tag 刷新时，值写入与配置导入分开；8.3.9 与 beta 不假定同一 API。没有实际可用合同则保留阻塞。

## 4. 记录模板和退出条件

每个版本分别保存以下结构化结论（路径由操作者决定，先保存在仓库外）：

| 字段 | 允许的结论 |
|---|---|
| environment / identity | 操作者声明与实际观察分列；标明版本/build/模块和合成数据 |
| mcp_discovery | passed / partial / blocked；页数、认证头名、无原始 token/cursor/session |
| target_openapi | passed / blocked；实际来源与独立认证结果 |
| view_contract | 实际发现的合同；未知则 blocked |
| baseline / write / readback / preview | 每步 passed / failed / unknown；含真实证据 |
| restore / restore_readback / restored_preview | 每步独立结论，恢复后内容摘要与画面 |
| refresh / conflict | 热更新、reload、未支持、未验证分别填写 |
| remaining_blockers | Artek 安装包、目标访问、Designer API、分页/并发等未完成项 |

**薄适配层闸门：** 与准备实现的版本路径对应的真实工具/目标 OpenAPI 已取得，且至少该路径完成并复核一次 View 写入 + 真实预览 + 恢复，才考虑该路径的薄适配。只通过其中一个版本，不得声称两个版本都已支持。官方 Designer 登录 API 仍未找到时不实现该能力；它不能被机器 API 或伪造登录界面代替。

本轮交付不附新 runtime fixture、不把历史证据重新标成已通过，也不自动实施上述写入、恢复或冲突步骤。
