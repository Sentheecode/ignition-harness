# 已打开的 Perspective 标签页在 View 写入和恢复后的表现

2026-11-18，在两份独立的 Linux 实验 Gateway 临时副本上，各执行一轮。8.3.9 build b2026082511，2027.2.0-beta1 build b2026110221。工程操作使用提交 `6f38951` 的研究适配层。实验项目为 HarnessLab。测试前通过各副本的官方管理页面重置已到期的试用计时。

| Gateway | 修改后看到新标题 | 恢复后看到原标题 | 两个阶段的主页面导航总数（含首次打开） |
|---|---:|---:|---:|
| [8.3.9](8.3.9.json) | 186 ms | 139 ms | 1 |
| [2027.2.0-beta1](beta1.json) | 155 ms | 108 ms | 1 |

1. 用临时 Chromium 上下文经官方 Web 登录，读取本实例 OpenAPI，导出基线 ZIP。在单个 Perspective 标签页等待既有 View 的 Title 标签可见。
2. 仅替换该标签文本。在浏览器记录单调时钟起点并启动 25 ms 间隔的 DOM 检查，随后通过适配层执行覆盖前的重新导出、比较和导入。记录可见的叶元素首次匹配完整目标文本的时刻，并用浏览器定位器确认可见。
3. 重新导出项目，逐条比较解压内容。确认与预期修改归档相符后，以这一版读回作为恢复前提，导入原始基线，再以同样方法观察原标题和检查读回。两版恢复后的 View SHA-256 均与各自基线一致。
4. 两个阶段均保持同一页面对象，校验浏览器 timeOrigin 和主框架导航计数。除初次打开外无主页面导航。以上耗时包含本地覆盖前检查、REST 导入和浏览器观测开销，每版本每方向仅一个样本。记录覆盖 DOM 文本可见性，不衡量屏幕实际呈现时刻或生产环境延迟。
